# SC-010 · 生态方治理神案闭环（标准范例）

> **视角**：治理｜**主角角色**：`OU→VU` ｜ **涉及平台**：OOS/OMS + VOS/VMS + Case
> **对应 A1.1**：02_B 角色派生 / 03_B OS 十二平台 / 03_C MS 十二管理集座 / 03_D OAS 底座
> **格式**：标准范例（业务流 + 精简时序图 + 增量 DDL + 事件契约 + 一致性验证）


## 一、业务背景

生态方(OU)将战略议题转为神案(Case/VOS)，VU 运营推进，经 OOS/OMS 审批形成闭环。

## 二、前置准备

- **角色**：`OU→VU`（由四根身份 HU/EU/GU/OU 派生，戴帽机制见 SC-014）
- **数据**：复用通用表 `iam.tenants` / `iam.users`（见 `00_场景范例索引.md` 通用表清单），以下仅列**本场景增量表**
- **权限**：`tenant_id` 多租户隔离；跨 OS 调用经 XBUS 事件总线

## 三、关键流程步骤

| # | 步骤 | 参与者流向 |
|:--|:--|:--|
| 1 | OU 发起议题(VOS/Case) |
| 2 | OMS 议题立项审批 |
| 3 | VU 组建运营专班 |
| 4 | Case 推进与协作(VOS) |
| 5 | 关键决策 OOS 审批 |
| 6 | 执行结果回填 |
| 7 | 结案归档 |
| 8 | 价值评估 VMS |

## 四、时序图（精简）

```mermaid
sequenceDiagram

        APP->>OS: 7. 结案归档
        OS->>OAS/datalake: 8. 价值评估 VMS
```

## 五、关键 API（RESTful）

| 方法 | 路径 | 说明 |
|:--|:--|:--|
| POST | `/api/{os}/...` | 创建类操作（写，走 Saga） |
| GET  | `/api/{os}/...` | 查询（同步 gRPC/HTTP） |
| POST | `/api/{ms}/...` | 管控规则/审批 |
| EVENT| `xbus.<事件类型>` | 跨 OS 异步事件（幂等） |

> 完整路径与字段见 `00_API_清单.md`（OpenAPI YAML）。

## 六、增量数据表 DDL

以下表为**本场景新增**，通用表（`iam.tenants`/`iam.users` 等）不重复定义：

- `vos.cases`
- `vos.case_tasks`
- `oms.decisions`
- `datalake.governance_metrics`

## 七、事件契约

复用统一事件类型（幂等键 = 事件类型 + 业务 ID，72h 超时，死信队列见 SC-013）：

`CaseCreated`, `CaseApproved`, `TaskAssigned`, `DecisionMade`, `CaseClosed`

## 八、与 A1.1 一致性验证

| 验证点 | 结果 |
|:--|:--|
| X 在 OS、M 在 MS | ✅ 交互在 APP/OS，审核管控在 MS |
| 层间正交（APP 不经 MS）| ✅ 均经 OS 中转 |
| 单一权威源 | ✅ 每类数据仅一个 owner |
| 四根身份 / 戴帽 | ✅ 主角由根身份派生 |
