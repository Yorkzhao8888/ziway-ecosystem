# SC-008 · 财务日清月结对账（标准范例）

> **视角**：职能/财务｜**主角角色**：`FU` ｜ **涉及平台**：FOS/FMS
> **对应 A1.1**：02_B 角色派生 / 03_B OS 十二平台 / 03_C MS 十二管理集座 / 03_D OAS 底座
> **格式**：标准范例（业务流 + 精简时序图 + 增量 DDL + 事件契约 + 一致性验证）


## 一、业务背景

财务角色(FU)通过 FOS 发起日清/月结，FMS 汇总多 OS 交易流水，对账并生成财务报表。

## 二、前置准备

- **角色**：`FU`（由四根身份 HU/EU/GU/OU 派生，戴帽机制见 SC-014）
- **数据**：复用通用表 `iam.tenants` / `iam.users`（见 `00_场景范例索引.md` 通用表清单），以下仅列**本场景增量表**
- **权限**：`tenant_id` 多租户隔离；跨 OS 调用经 XBUS 事件总线

## 三、关键流程步骤

| # | 步骤 | 参与者流向 |
|:--|:--|:--|
| 1 | FU 登录 FOS(财务工作台) |
| 2 | FMS 拉取各 OS 交易流水 |
| 3 | 日清对账(逐笔匹配) |
| 4 | 月结汇总与调账 |
| 5 | 财务报表生成 |
| 6 | 审批签字(OOS) |
| 7 | 归档至 datalake |
| 8 | 异常告警 GMS |


## 五、关键 API（RESTful）

| 方法 | 路径 | 说明 |
|:--|:--|:--|
| POST | `/api/{os}/...` | 创建类操作（写，走 Saga） |
| GET  | `/api/{os}/...` | 查询（同步 gRPC/HTTP） |
| POST | `/api/{ms}/...` | 管控规则/审批 |
| EVENT| `xbus.<事件类型>` | 跨 OS 异步事件（幂等） |

> 完整路径与字段见 `00_API_清单.md`（OpenAPI YAML）。

## 六、增量数据表 DDL

以下表为**本场景新增**，通用表（`iam.tenants`/`iam.users` 等）不重复定义：

- `fms.daily_reconciliations`
- `fms.monthly_statements`
- `fms.ledger`
- `datalake.finance_metrics`

## 七、事件契约

复用统一事件类型（幂等键 = 事件类型 + 业务 ID，72h 超时，死信队列见 SC-013）：

`ReconciliationStarted`, `DailyCleared`, `MonthlyClosed`, `StatementApproved`, `LedgerArchived`

## 八、与 A1.1 一致性验证

| 验证点 | 结果 |
|:--|:--|
| X 在 OS、M 在 MS | ✅ 交互在 APP/OS，审核管控在 MS |
| 层间正交（APP 不经 MS）| ✅ 均经 OS 中转 |
| 单一权威源 | ✅ 每类数据仅一个 owner |
| 四根身份 / 戴帽 | ✅ 主角由根身份派生 |
| 跨 OS 协作经 XBUS | ✅ 多场景涉及（详见 SC-013）|
| EOS=供给运营 / EMS=供给管理 | ✅ 命名规范统一 |
