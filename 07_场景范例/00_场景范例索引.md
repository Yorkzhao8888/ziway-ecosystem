## 四、统一事件契约

所有跨 OS 事件遵循：
- **幂等键** = 事件类型 + 业务 ID
- **超时** = 72h（Saga 长事务）
- **死信队列** = `xbus.dead_letter_queue`（SC-013）
- **权威源** = 每类数据单一 owner（SC-013）

事件类型全集：见各场景 §七（去重后约 60 个，详见 `00_事件类型汇总.md` 如需拆分）。

## 五、命名与一致性约束

- 平台层 `X-OS`、管理层 `X-MS`；`EOS=供给运营`、`EMS=供给管理控制`
- APP 无 `ziway-` 前缀；神案为 `Case`（非 Xcase）
- 五层：U / APP / OS / MS / OAS
- 价值链：TM → DM → EM → CM

## 六、格式约定

- **锚点(SC-001)**：超完整（时序图 + 完整 DDL + 事件详情）
- **标准范例(SC-002~014)**：业务流 + 精简时序图 + **仅增量 DDL** + 事件引用
