## 二、编排模式 vs 直通模式

### 编排模式（4 个）—— P0 部署独立进程

| OS | 职责 |
|:----|:----|
| **COS** | 零售业务编排（CMS 客户 + DMS 商家 → Mall）|
| **DOS** | 门店/事业经营编排（DMS + HMS + FMS → Shop）|
| **IOS** | 资本运营编排（IMS + FMS → 投资专案）|
| **VOS** | 专案/治理运营编排（GMS + OMS + VMS → Case）|

### 直通模式（8 个）—— P0 不部署独立进程

直通 OS **保留代码结构，但 P0 不启动独立服务**。请求经 Kong 网关按路由规则直接转发到对应 MS。

| OS | 直通目标 MS | Kong 路由规则 |
|:----:|:------------:|:-------------|
| AOS | AMS | `/api/ambs/*` → AMS |
| POS | PMS | `/api/pmbs/*` → PMS |
| HOS | HMS | `/api/hmbs/*` → HMS |
| EOS | EMS | `/api/embs/*` → EMS |
| SOS | SMS | `/api/smbs/*` → SMS |
| FOS | FMS | `/api/fmbs/*` → FMS |
| GOS | GMS | `/api/gmbs/*` → GMS |
| OOS | OMS | `/api/ombs/*` → OMS |

> **升级条件**：当直通 OS 需要编排 ≥2 个业务 MS 时，自动升级为编排模式，部署独立进程。

## 三、六位一体生态

| 平台 | 角色 | 定位 |
|:----:|:----:|:----|
| COS | 零售运营 | 流量入口 |
| DOS | 事业经营 | 利润中心 |
| EOS | 供给运营 | 效率引擎 |
| **POS** | **产品研发（支撑台）** | **支撑以上三大平台** |
| HOS | 人才职聘 | 人力中枢 |
| VOS | 专案运营 | 协同中枢 |

### POS 支撑关系

```
POS（产品研发）
  ├── 支撑 COS（流量：产品力→转化）
  ├── 支撑 DOS（利润：产品数据→经营决策）
  └── 支撑 EOS（效率：标准化商品→精准撮合）
```

> POS 不直接面向 CU/EU 等终端用户，所有产品能力通过 COS/DOS/EOS 的 APP 触达。
