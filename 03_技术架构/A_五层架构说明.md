# 五层架构说明

> 知味生态的技术骨架：从用户到技术底座，五层严格分层、依赖只指向下层。

---

## 一、五层全景

```
┌─────────────────────────────────────────────────────┐
│  U 用户层                                           │
│  HU（原子身份）+ CU/DU/PU/EU/OU（戴帽角色）          │
├─────────────────────────────────────────────────────┤
│  APP 智能终端层（8 个）                              │
│  Mall / Shop / Lab / Market / Dyard / Case /        │
│  Agent / Mate                                       │
├─────────────────────────────────────────────────────┤
│  OS 城市功能区（12 个）                             │
│  [编排模式] COS / DOS / IOS / VOS                │
│  [直通模式] AOS / POS / HOS / EOS / SOS /       │
│             FOS / GOS / OOS                       │
├─────────────────────────────────────────────────────┤
│  MS 管理集座（12 + 1 个）                           │
│  业务 MS(11) + AMS(MS-P)                         │
├─────────────────────────────────────────────────────┤
│  OAS 技术底座（1 个部署项目）                        │
│  /owner/* · /admin/* · /internal/*                   │
└─────────────────────────────────────────────────────┘
```

---

## 二、各层职责

### 2.1 U 用户层

| 要素 | 说明 |
|:----|:----|
| 原子身份 | HU（个人/工作者）|
| 根身份 | OU（生态方）/ HU（个人）/ EU（企业）/ GU（政府）|
| 派生角色 | CU / DU / PU / SU / VU / FU / IU（戴帽获得）|
| 独立根身份 | OU / AU |

详细定义见 `02_角色体系/A_四根身份模型.md`。

### 2.2 APP 智能终端层（8 个）

| APP | 面向角色 | 主 OS | 中文名 |
|:---:|:--------:|:------:|:------:|
| Mall | CU / DU | COS | 商城 |
| Shop | DU | DOS | 门店 |
| Lab | PU | **POS** | 创研（产品孵化）|
| Market | EU | EOS | 集市（+Support 子模块）|
| Dyard | SU / 开发者 | SOS（编排 SMS）| 神域资源 |
| Case | OU/VU/FU/IU/AU | VOS/OOS | 治理协同 |
| Agent | 所有用户 | —（OAS 底座）| 智体 |
| Mate | HU（伙伴协作）| HOS | 伙伴 |

> **注意**：OAS 不是 APP，它是后端服务项目，其功能通过 Case 等 APP 的管理入口访问。

### 2.4 MS 管理集座（12 + 1 个）

详见 `03_技术架构/C_MS十二管理集座.md`。

### 2.5 OAS 技术底座（1 个部署项目）

## 三、层间依赖规则

| 规则 | 说明 |
|:----|:----|
| **依赖只指向下层** | APP → OS → MS → OAS，禁止反向依赖 |
| **同层不直接调用** | 两个 OS 之间不直接调用，通过 XBUS 事件或 MS 编排 |
| **跨层必须通过接口** | U 层不直接访问 MS/OAS，必须经 APP → OS |

---

## 四、数据流模式

| 模式 | 流向 | 说明 |
|:----:|:----:|:----|
| 业务执行 | APP → OS → MS | 标准业务请求 |
| 治理协同 | Case → MS | OU/AU 通过治理入口操作 MS |
| 技术底座 | Case + OAS → AMS | AU 通过 OAS 管理基础设施 |
